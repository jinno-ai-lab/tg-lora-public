## bug の機構（4-link collision chain）

`prefix_feature_cache` は frozen prefix 層の forward-pass 活性（hidden_states / attention_mask / labels / position_ids）を disk に永続化し再利用する最適化。cache path は metadata の SHA-256 から導出されるため、**cached content に影響するが fingerprint にない field** は silent collision を起こす。

| link | 主張 | 実コード証拠 |
|------|------|-------------|
| ① | `train_on_prompt` は labels を load-time で反転する（file bake でない） | `train_tg_lora.py:1002` `load_dataset(..., train_on_prompt=cfg.training.get("train_on_prompt", False))`〔src.data〕・`test_build_seed_dataset.py:139 test_train_on_prompt_keeps_prompt_labels`〔True=prompt labels 保持 / False=`labels=-100` mask〕・`run_freeze_validloss_ci_9b.py:40`「`train_on_prompt=False`: ChatML user-turn is masked with `labels=-100`」 |
| ② | cached labels は入力 dataset から verbatim copy され load 時に再導出されない | `prefix_feature_cache.py:445` `labels=batch["labels"][row].detach().cpu().clone()`〔`build_prefix_feature_dataset` 内〕・保存 tensor `_labels`〔同 124-125・202-240 `_extract_prefix_feature_storage`〕 |
| ③ | fingerprint は `train_on_prompt` を除外 | `build_prefix_feature_cache_metadata` の metadata dict〔format_version + dataset path/size/mtime + model + seed + max_seq_len + split_layer + lora_r/alpha/dropout/target_modules + trainable_lora_scope の 12 field〕に `train_on_prompt` 不在 |
| ④ | 到達可能（default ON） | `config_schema.py:90` `prefix_feature_cache_train: bool = True`〔default〕・`_maybe_cache_dataset` が train/valid_quick/valid_full で enabled 時に呼ばれる |

**collision**: run A（`train_on_prompt=False`・masked labels・dataset file X）が cache 構築 → path = SHA(metadata without train_on_prompt)。run B（`train_on_prompt=True`・unmasked labels・同 file X）は同一 metadata → 同一 path → A の masked-labels cache を**黙って再利用** → B は completion のみで訓練され prompt-loss を欠く（operator の意図と逆）。逆方向も同様（silent contamination）。default が `False` で大半の run が同値なため観測されにくい latent bug だが、`train_on_prompt` 切替え + cache 再利用で即座に発火。

## fix（fail-loud 設計）

`build_prefix_feature_cache_metadata` に `train_on_prompt: bool` を**必須 keyword-only 引数**として追加し、metadata dict に `"train_on_prompt": bool(train_on_prompt)` を stamp。

- **必須（default なし）の理由**: cache-collision bug の本質は「field の黙名的 default」が cached content と整合しないこと。引数を必須にすると、将来の producer path が `train_on_prompt` を渡し忘れた瞬間に `TypeError` で fail-loud する（silent default を構造的に排除）。repo の fail-loud culture（atomic-write / load-side integrity / producer Pydantic gate）と同一方針。
- **3 prod call site 接続**:
  - `train_tg_lora.py:1112`（`_maybe_cache_dataset`）→ `train_on_prompt=bool(cfg.training.get("train_on_prompt", False))`〔既存 line 1002 と同一 access 形式〕
  - `async_cache_builder.py:197`（`_build_one`）→ `train_on_prompt=bool(self._cfg.training.get("train_on_prompt", False))`〔既存 `.get` pattern と整合・test で OmegaConf cfg 確認済〕
  - `precompute_prefix_cache_parallel.py:198`（`_build_worker_configs`）→ `train_on_prompt=bool(getattr(cfg.training, "train_on_prompt", False))`〔**getattr 必須**: test は Pydantic `TrainingConfig`・runtime は `OmegaConf.load` → ともに属性 access 可・`.get` は Pydantic で不可〕
- **6 test helper site 更新**: `_default_metadata` base dict〔test_prefix_feature_cache / test_compare_prefix_smoke / test_prefix_feature_cache_robustness〕+ 直接 call〔test_prefix_cache_coverage_0091 / test_async_cache_builder ×2〕に `train_on_prompt=False` を追加。
