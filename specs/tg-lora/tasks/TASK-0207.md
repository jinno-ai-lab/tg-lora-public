## bug の機構（4-link collision chain・ACTIVATION 側）

`prefix_feature_cache` は frozen prefix 層の forward-pass 活性（hidden_states / attention_mask / labels / position_ids）を disk 永続化し再利用。cache path は metadata の SHA-256 から導出されるため、**cached content に影響するが fingerprint にない field** は silent collision を起こす。TASK-0206 は LABEL 側（`train_on_prompt`）を閉鎖したが ACTIVATION 側（hidden_states を駆動する model 精度）は残っていた。

| link | 主張 | 実コード証拠 |
|------|------|-------------|
| ① | cached hidden_states は base model の forward-pass（load-time precision に依存） | `prefix_feature_cache.py:401-407` `build_prefix_feature_dataset` 内の forward hook: `decoder_layers[split_layer_idx].register_forward_pre_hook(_hook_fn, with_kwargs=True)` が `model(input_ids=batch["input_ids"], attention_mask=batch["attention_mask"])` の出力を capture・`hidden_batch = captured[0]` を cache |
| ② | model precision は load-time config で決まる（file bake でない） | `load_model.py:35-42 build_bnb_config`: `cfg.model.get("load_in_4bit")` が True のみ `BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_quant_type=cfg.model.get("bnb_4bit_quant_type", "nf4"), bnb_4bit_compute_dtype=...)` を構築・False なら `dtype` で weight cast〔`config_schema.py:47-50 ModelConfig`: `dtype="bfloat16"` / `load_in_4bit=True` / `bnb_4bit_quant_type="nf4"` / `bnb_4bit_compute_dtype="bfloat16"` は runtime config〕 |
| ③ | fingerprint は精度 field を除外（`model_name` のみ proxy） | `build_prefix_feature_cache_metadata` の metadata dict に `dtype` / `load_in_4bit` / `bnb_4bit_quant_type` / `bnb_4bit_compute_dtype` 不在〔TASK-0206 修了時点で model_name のみが精度を proxy〕 |
| ④ | 到達可能（default ON + cross-run reuse） | `config_schema.py:48 load_in_4bit: bool = True`〔default〕・cache `mode="reuse"` で同一 cache_dir を跨 run 再利用 |

**collision**: run A（`load_in_4bit=True` / nf4・dataset file X・model M）が cache 構築 → path = SHA(metadata without precision)。run B（`load_in_4bit=False` / bf16・同 file X・同 model M）は同一 metadata → 同一 path → A の nf4-rounding 済み活性を**黙って再利用** → B は自身の forward が生成する bf16 活性でなく nf4 活性に対して LoRA suffix を訓練（shifted objective・operator に無通告）。nf4↔fp4 / bf16↔fp16 compute の切替えでも同様。model 精度は LoRA 実験の主要軸（VRAM 拠出のための 4-bit 切替え等）のため、cross-run で即座に発火する latent bug。

## fix（fail-loud 設計）

`build_prefix_feature_cache_metadata` に `dtype: str` / `load_in_4bit: bool` / `bnb_4bit_quant_type: str` / `bnb_4bit_compute_dtype: str` を**必須 keyword-only 引数**として追加し、metadata dict に `"dtype": str(dtype)` / `"load_in_4bit": bool(load_in_4bit)` / `"bnb_4bit_quant_type": str(bnb_4bit_quant_type)` / `"bnb_4bit_compute_dtype": str(bnb_4bit_compute_dtype)` を stamp。

- **必須（default なし）の理由**: TASK-0206 と同一方針。cache-collision bug の本質は「field の黙名的 default」。4 field を必須にすると将来の producer path が渡し忘れた瞬間に `TypeError` で fail-loud（silent default を構造排除）。4 field は forward precision を完全に決定する（`load_in_4bit` の値で一部は no-op になるが、全て stamp することで精度変更 config の列挙が完全に保たれる — 11th derived-float entry が陥った「cosmetic と早合点して見逃す」過ちを回避）。
- **cast の理由**: `str()` / `bool()` は OmegaConf node と Pydantic value の直列化を一致させ、content-addressed key の決定性を保証（`train_on_prompt=bool(...)` と同様）。
- **3 prod call site 接続**:
  - `train_tg_lora.py:1112`（`_maybe_cache_dataset`）→ `cfg.model.dtype` 等〔既存 `cfg.model.name_or_path` と同一属性 access 形式・OmegaConf runtime〕
  - `async_cache_builder.py:197`（`_build_one`）→ `self._cfg.model.dtype` 等〔既存 `.model.name_or_path` と整合〕
  - `precompute_prefix_cache_parallel.py:198` → `cfg.model.dtype` 等〔test は Pydantic `TGLoRAConfig(model=ModelConfig(...))`・runtime は OmegaConf・ともに属性 access 可。model field は Pydantic default を持つため `getattr` 不要・`train_on_prompt` の getattr pattern とは別根拠〕
- **6 test helper site 更新**: `_default_metadata` base dict〔test_prefix_feature_cache / test_compare_prefix_smoke / test_prefix_feature_cache_robustness〕+ 直接 call〔test_prefix_cache_coverage_0091 / test_async_cache_builder ×2〕に 4 field 追加。`test_async_cache_builder` の disk-hit test は metadata 精度を `_make_cfg` の実値（`float32` / `load_in_4bit=False`）に一致させる必要があり、bfloat16/True だと path 不一致で rebuild するため float32/False に調整（builder と test の fingerprint 一致性の保証）。
