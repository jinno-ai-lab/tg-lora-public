## Context (why this is the lever, not peripheral hardening)

TASK-0213 (`7a5c535`) surfaced the GOAL §4-247 full-backprop baseline verdict per leg, and
TASK-0214 (`5e7009b`) wired the `--n-baseline 3` arm into the heterogeneous full-budget
target. That heterogeneous full-budget baseline run is **in-flight as of 2026-07-27**
(fired 07:57 on public Dolly, 12 arms, ~4h) — when it lands and is harvested into
`tests/fixtures/freeze_validloss_ci_9b_full_heterogeneous.json`, the deposit flips from
`n_baseline=0`/`baseline=null` to a measured verdict.

The decision surface renders that block **adaptively** (`format_decision` reads
`qp["answered"]`), so the "Quality preservation" block would correctly say
`heterogeneous [SURPASSES|TIES|INFERIOR]`. But the **SHIP rationale** string hardcoded
`"homogeneous SURPASSES; heterogeneous unanswered — … only a GPU window stands between
UNANSWERED and the reading"`. After harvest those two would **directly contradict** in the
same report — the recommendation citing a state the surfaced evidence no longer carries.
That is a P0 科学誠実性 break: the one place the operator reads the *call* would disagree
with the measured *evidence* sitting three lines above it.

## The gap (evidence-honesty, GPU-free)

`assess_section4_decision` already computed `quality_preservation` (per TASK-0213) but the
SHIP `rationale` re-stated the per-leg status as a **hardcoded literal** instead of reading
it back. The hardcoded text was correct *today* (heterogeneous genuinely unanswered) but
brittle: nothing recomputed it when the deposit changed, and nothing tested the answered-
heterogeneous rendering of the *rationale* (only of the report block).

## Fix (small-diff, additive — derive, don't restate)

1. New `_quality_preservation_clause(quality_preservation)`: renders the per-leg clause FROM
   the surfaced evidence — answered leg → `"{label} {verdict}"`; unanswered leg → the
   wired-but-unfired clause. Order follows `quality_preservation` insertion order
   (homogeneous then heterogeneous), matching the `legs` construction order.
2. SHIP rationale embeds `_quality_preservation_clause(quality_preservation)` instead of the
   hardcoded parenthetical.

**Against the current harvested deposits the derived clause is byte-identical to the prior
hardcoded text** (homogeneous answered ⇒ "homogeneous SURPASSES"; heterogeneous unanswered ⇒
the long clause) — zero behavior change now, and it auto-corrects the moment the in-flight
deposit is harvested, with no manual string edit and no chance of the rationale lagging the
evidence.
