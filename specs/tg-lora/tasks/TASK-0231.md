### 実在 defect: prediction 側は堅牢だが gold 側は無ガードの非対称

直近2 commit が同一 defect class を閉じた:

- `1d6e7d4`（eval_format）: `all(k in parsed for k in required_keys)` が `isinstance(dict)` ガードなし → valid-JSON だが非 dict（`42`/`true`/`null`）で `k in parsed` が未 catch の `TypeError`。
- `a5506f7`（run_metrics）: `_read_existing_provenance` の `.get("run_id")` が非 dict 行で `AttributeError`。

headline metric `src/eval/eval_json_extraction.py` には**同一クラスの残存 site** があった:

- **prediction 側**は `extract_json`/`_first_json_object` が `isinstance(obj, dict)` で `dict | None` に堅牢化済み（L60/L119）。

両 generation wrapper（`jsonex_generation.py:80`・`json_generation.py:111`）は gold を `json.loads(record["completion"])` で組み立てて `score_json_extraction` → `score_single` へ直送する。gold completion が valid JSON だが**非 dict**（配列 `[1,2,3]` / `42` / `true` / `null` / bare string — データパイプラインの誤生成や手編集で起こりうる）の場合、`json.loads` は成功し、`gold.get("type")` が未 catch の `AttributeError`（`'list' object has no attribute 'get'`）を raise して**JSON-extraction eval 全体を abort** する。これは prediction 側ガードとの非対称であり、`1d6e7d4` が指摘した「sibling は既に guard しているのにここだけしていない」と同形。

## 変更（src 1 file + test 1 file）

### 1. `src/eval/eval_json_extraction.py` `score_single` — gold の `isinstance(dict)` ガード

`valid`/`strict_valid` 計算の直後に早期 return を挿入。非 dict gold は typed schema と照合できないため、prediction の validity のみ採点し、type/field/exact は 0、`computed_accuracy` は `None`（person record と同様に aggregate 平均から除外）のまま返す:

```python
if not isinstance(gold, dict):
    result["combined"] = 0.3 * result["valid"]
    return result
```

happy path（dict gold）は byte-identical — ガードをスキップして以降の全行がそのまま実行される。`combined` の算出も非 dict 时 `0.3*valid + 0.2*0 + 0.5*0 = 0.3*valid` で正常経路の式と一致。

### 2. `tests/test_eval_json_extraction.py` `TestScoreSingle::test_non_dict_gold_does_not_crash_scorer`

非 dict gold 5 型（list/scalar/bool/None/string）で `score_single` が crash せず sane な零スコアを返すこと、および wrapper の実入口である `score_json_extraction([pred,pred], [[1,2,3], 42])` が aggregate 経路でも crash しないことを主張。
