## 背景

`ce48610` は 3 cache producer（train_tg_lora / async_cache_builder / precompute_prefix_cache_parallel）の inline 指紋構築を単一の `prefix_feature_cache_metadata_from_config()` へ統合する設計を着地させ、まず train_tg_lora を接続した。残る 2 producer は依然として旧 idiom を inline していた:

1. **`src/training/async_cache_builder.py`** — `cfg.training.get(...)`（dict-style・Pydantic TrainingConfig では AttributeError になりうる idiom）+ **事前解決 constructor 引数 `trainable_lora_scope`**。この引数が指紋の唯一の乖離 surface: caller が cfg と異なる値を渡せば、同一 cfg の他 producer と別 cache path を鋳造する。
2. **`scripts/precompute_prefix_cache_parallel.py`** — `cfg.training.prefix_feature_cache_share_across_seeds` を **default なし**で読み取り（OmegaConf 未設定時に乖離）+ `getattr()` idiom。

## 実装内容

1. **`src/training/async_cache_builder.py`**:
   - `_build_one` の指紋構築を `_metadata_for(dataset_path)` シームへ置換 → `prefix_feature_cache_metadata_from_config(self._cfg, ...)` を呼ぶ。`trainable_lora_scope` を含む全 label/precision-affecting 字段を **cfg から**読む。
   - constructor 引数 `trainable_lora_scope` を**削除**（乖離 surface の除去。無効 scope は上流の `config_schema.TrainableLoraScope` literal が拒否するため検証は冗長）。`test_rejects_empty_trainable_lora_scope` も削除し跡地に理由コメント。
   - happy path の指紋 byte は不変: caller（train_tg_lora L988）は元々 `cfg.training.get("trainable_lora_scope", "all")` の解決値を渡しており、helper の default 付き読み取りと一致 → 既存 on-disk cache は有効。
2. **`scripts/precompute_prefix_cache_parallel.py`**: `_build_worker_configs` の指紋構築を同 helper へ置換。default なし読み取りだった share flag は helper 側 default `False` に正規化（Pydantic スキーマの default と一致）。
3. **`src/training/train_tg_lora.py`**: AsyncCacheBuilder 呼び出しから削除引数を除去 + 設計意図コメント。
4. **tests（5 ファイル）**:
   - async 3 スイートの fixture に `training.trainable_lora_scope: "last_25_percent"` を追加（旧 constructor 引数値を cfg 側へ移設・指紋入力不変）・全呼び出しから削除引数を除去。
   - `test_async_build_disk_hit_skips_build` / `test_async_force_rebuild_ignores_disk_cache`: 手書き `build_prefix_feature_cache_metadata` 呼び出しを**同一 shared mapping 呼び出しへ置換** — 「任意の producer がこの path に書いた cache が replay される」不変条件を構造的に表現。
   - `test_precompute_prefix_cache_parallel.py`: patch ター旧属性名を更新。
   - **`tests/test_prefix_feature_cache.py::TestCrossProducerFingerprintIdentity`（新規・2 テスト）**:
     - `test_all_three_producers_mint_byte_identical_metadata` — 同一値の OmegaConf cfg（AsyncCacheBuilder の runtime model）+ Pydantic cfg（precompute の検証済み model）から、(a) shared mapping 直接・(b) `AsyncCacheBuilder._metadata_for`・(c) `_build_worker_configs` の plan metadata + cache_path が**三者 byte-identical** であることを等値で pin。非自明性保証として `train_on_prompt=True` / `trainable_lora_scope="last_25_percent"`（非 default 値）が指紋へ到達していることを別途 assert。
     - `test_scope_change_in_cfg_changes_builder_fingerprint_without_ctor_arg` — builder の指紋が `cfg.training.trainable_lora_scope` に追従し scope 差が cache path 差になることを pin（削除した constructor 引数の乖離 surface が再発したら失敗）。
