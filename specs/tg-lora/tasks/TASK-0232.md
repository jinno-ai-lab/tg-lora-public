### 選定: load-bearing 非 eval surface の残存 defect

cascade 終了後、endorsed bug-fix pattern を **eval 以外**の load-bearing 経路へ振り向けた。`680bfa5` と `a5506f7` が実証済みの defect class —「`json.loads`/`orjson.loads` は成功するが非 dict（配列/スカラー）を返し、直後の `.get()` が未 catch の `AttributeError` で consumer 全体を落とす」— の残存 site を Explore agent で網羅探索した結果、`scripts/compare_runs.py::load_run` を選定した根拠:

- **production 経由で到達可能**: `load_run` は `main()` の two-run 比較経路（`compare_runs.py:1035-1036`・`load_run(Path(args.baseline))` / `load_run(Path(args.tg_lora))`）から呼ばれ、`Makefile:508`/`:767`（`scripts/compare_runs.py` = `make compare` 相当）で起動される。multi-run の `gather_runs` 経路は既に hardened `parse_jsonl`（680bfa5）を使うが、two-run 経路の `load_run` は独自の unguarded loop のままだった。
- **実 crash**: `run_metrics.jsonl` に非 dict 行（破損/手編集の bare 配列・スカラー）が1行でもあれば `rec.get("type")` が `AttributeError`（`'list' object has no attribute 'get'`）を raise し、比較レポート全体を abort する。680bfa5/a5506f7 がこれらと同じ file の非 dict 行を実証済み（real corpus）。
- **非 eval**: run-comparison tooling であり、json-extraction metric ではない。cascade の再流入ではない。

## 変更（src 1 file + test 1 file）

### 1. `scripts/compare_runs.py::load_run` — `isinstance(rec, dict)` ガード

`rec = orjson.loads(line)` の直後に早期 `continue` を挿入。非 dict 行を skip し、dict 行のみ `rec.get("type")` で分類。happy path（全行 dict）は byte-identical — ガードを通過する行のみが以降の分類ロジックを実行し、header/records/footer の結果は不変。genuine invalid-JSON は `orjson.loads` で従来通り raise（fail-loud 維持）。

```python
rec = orjson.loads(line)
if not isinstance(rec, dict):
    continue
t = rec.get("type", "step")
```

`parse_jsonl`（680bfa5 hardened・本 file が既に import 済み）への route も検討したが、`parse_jsonl` は invalid-JSON で `ValueError`（line no 付き）を raise し、`load_run` の現行 `orjson.JSONDecodeError` と例外型が変わるため caller の error handling を変えるリスクがある。最小・集中・挙動不変の isinstance ガード（680bfa5 と同一 pattern）を採用した。

### 2. `tests/test_compare_runs.py::test_load_run_skips_non_dict_jsonl_lines`

valid dict record の間に非 dict 行（配列 `[1,2,3]` / スカラー `42`）を挟んだ metrics file で `load_run` が crash せず、非 dict 行を skip して valid record のみ返すことを主張。
