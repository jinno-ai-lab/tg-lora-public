## 決定論（なぜ 102 件を直さず `--select` pin か）

102+10 件の style 修正は feedback が明示的に忌避する「polish-churn / refinement 純負」に該当する。一方、guard を **docstring が当初から意図した canonical set (E4/E7/E9/F) へ `--select` pin** すると:

1. **不変性が決定論化**される — ruff の default（moving target）に依存せず、版を跨いで同じ判定。
2. **意図保存** — 両 guard は元来「default = E4/E7/E9/F」を想定して書かれた（helper comment にも「ruff's default rule set is E4/E7/E9/F」と明記）。pin は docstring 通りの挙動を**正しく実装**する（weaken ではない）。
3. **defect class を網羅** — E741/F401/F841/F821 は全て E7/F 配下。pin しても guard の本来目的（これらの回帰検出）は完全に保持される（下記 mutation で証明）。
4. **churn 最小** — 30 ファイル・112 件の style 書き換えではなく、各 guard の `_run_ruff` 呼び出し 1 箇所の select 指定のみ。src/ は 1 byte も変更しない。

`--select` は ruff の default 選択を**置換**する（追加ではない）— これが pin を機能させる原理であり、同時に既存の W605 guard（`select=("W605",)`）が「default + W605」でなく「W605 のみ」を実行して green を保つ理由でもある（本修正でこの挙動は不変）。
