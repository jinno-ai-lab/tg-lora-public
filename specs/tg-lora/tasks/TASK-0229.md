## 動機（catalog completeness claim が未閉鎖だった事実）

TASK-0226 は §4 surface を fixture-vs-live 構造 predicate 比較で pinned し（`TestSnapshotFixtureIntegrity`）、TASK-0228 は派生 predicate 2 件（`run_executable_here` / `recover_rerun_blocked_by_src_data`）を追加して固定 key リストを 8 件へ拡張した。しかし**両 TASK の pin は固定 key リストの反復比較**であり、以下の残存 gap があった:

- **既知 predicate の値 drift** は検知する（固定リスト内 key の値が変われば RED）✓
- **既知 predicate の消失** は検知する（`live_payload[key]` が KeyError → RED）✓
- **新規 predicate の追加** は検知**しない** ✗ — refactor が snapshot に新たな load-bearing top-level predicate（例: 新しい `xxx_status` gate）を追加しても、固定 8-key リストに無ければ**silent に CI 緑で通過**してしまう

これが feedback bullet 3 が名指す **「a refactor that silently drops/ adds a contract term blocks the PR, not slip through」** の、まさに**追加方向の slip-through 形状**である（消失方向は既存 test が KeyError で捕えるが、追加方向は抜け穴だった）。「catalog completeness is the **load-bearing** claim」という表現の核心は、catalog が**網羅的であること自体**が主張対象である点にある。

### `tests/test_section4_operator_decision.py` — `TestSnapshotFixtureIntegrity` に `test_top_level_predicate_catalog_is_complete` 追加

snapshot の **top-level key 全集合**が `{pinned} ∪ {allowlisted-non-load-bearing}` に**厳密一致**することを主張する:

```python
PINNED_TOP_LEVEL = {              # 固定リスト pin 対象 8 件（TASK-0226 + 0228）
    "arc_complete", "landed_decision", "awaiting_operator_decision",
    "recommendation", "verdict_worker_status", "src_data_status",

}
PINNED_BY_SUBTEST = {"legs", "quality_preservation", "branches"}  # 専用 sub-test で pin 済み
ALLOWLISTED_NON_LOAD_BEARING = {  # 意図的に byte-pin 対象外（各々明示的列挙・新 key の隠れ場なし）
    "verdict_worker_reason",              # verdict_worker_status からの派生文字列

}

assert set(live_payload) == set(fixture_payload)   # live==fixture key set（帰属の正確化）
assert set(live_payload) == catalog                 # 網羅性本体
```

設計上の要点:

- **新規 meta-test ではない固定リスト拡張ではなく、全集合の網羅性主張** — 固定リスト方式では到達できなかった「新規 predicate 追加の slip-through」を閉じる。新規 load-bearing predicate は意識的に `PINNED_TOP_LEVEL`（or 専用 sub-test）へ、新規非 load-bearing key は `ALLOWLISTED_NON_LOAD_BEARING` へ、それぞれ**意識的決定**を強要する。
- **allowlist は wildcard でなく各 key 明示列挙** — 新 key が非 load-bearing の山に紛れ込めない。
- **bullet 4「stop adding new terms」への抵触なし** — PURPOSE.md「次の一手」追記ではなく test 追加＝freeze guard（`tests/test_purpose_next_steps_freeze.py`・frozen baseline 97 追記）不触。
- **script 側（`scripts/section4_operator_decision.py`）は不変**・**fixture（`tests/fixtures/section4_decision_snapshot_2026-07-28.json`）も不変**（mutation は全て revert 済み・git status で test file のみ modified）。
